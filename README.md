# AI 기반 처방·조제 검수 및 복약관리 통합 시스템

졸업작품 8조의 멀티모달 Vision AI 기반 의약품 인식 및 Human-AI 조제검수·복약지원 프로젝트입니다.

처방전 정보와 실제 조제 의약품의 종류·함량·수량을 인식하고 비교하여 약사의 최종검수를 지원합니다. 검수가 완료된 정보를 환자 앱과 연결하여 처방정보와 복약지도를 다시 확인하고 복약관리를 이어갈 수 있도록 하는 통합 시스템을 목표로 합니다.

## 현재 상태

현재 저장소에는 프로젝트 기획서와 시스템 흐름도가 정리되어 있습니다. 구현 코드와 실행 방법은 개발 진행에 따라 추가할 예정입니다. 아래 기능과 기술 스택은 기획 기준이며 구현 완료를 의미하지 않습니다.

**개발 진행 상황, 데이터 확보 수준, 실험 결과, 팀 협의 및 지도교수 피드백에 따라 기능 범위·대상 의약품·기술 스택·하드웨어·일정은 변경될 수 있습니다.** 최신 계획과 진행 현황은 [프로젝트 기획서](docs/project-plan.md)에서 관리합니다.

## 프로젝트 목적

- 처방정보와 실제 조제정보를 구조화하여 반복적인 검수 업무를 지원합니다.
- 오선택·누락·혼입·수량 오류·함량 오류를 표시하고 약사의 확인을 돕습니다.
- 약사가 확인한 처방·복약정보를 환자의 복약관리로 연결합니다.

AI가 인식·비교 결과를 제공하고 약사가 최종 조제 적합 여부를 판단하는 Human-AI 협업 구조를 적용합니다. 식별이 불확실하거나 비교에 필요한 정보가 부족하면 자동 정상 판정하지 않고 재확인을 요청합니다.

## 주요 기능 계획

| 기능 | 내용 |
| --- | --- |
| 처방정보 인식 | QR·바코드 또는 OCR로 약품명·함량·수량·복용횟수·복용기간 추출 |
| 실제 의약품 인식 | Vision AI·각인 OCR·의약품 Metadata를 결합하여 약포지 속 의약품 식별 |
| 통약·PTP 검수 | 박스·용기의 제품명·함량·포장단위 인식 및 낱개 PTP의 알약 수량 확인 |
| 처방·조제 비교 | 공통 의약품 DB를 기준으로 처방정보와 실제 조제정보 비교 |
| 약사용 WEB | 인식 결과·신뢰도·오류 확인, 정보 수정, 최종검수 및 이력 관리 |
| 환자용 APP | 처방·복약지도 확인, 복용 알림, 즐겨찾기 및 과거 처방정보 조회 |
| 폐의약품 배출정보 | 위치 또는 지역 검색을 통한 수거 가능 장소 안내 |

## 시스템 흐름

```text
처방전 QR·바코드 / OCR → 처방정보 표준화 ────────┐
                                              ├→ 처방·조제 비교
촬영 Station → 실제 의약품 인식 → 조제정보 표준화 ┘
    → 약사용 WEB → 약사 최종검수 → 환자 APP 복약관리
```

처방정보와 실제 조제정보는 독립적으로 생성하고 동일한 공통 의약품 Master DB를 참조합니다. 초기 처방·조제 비교 모듈은 규칙 기반으로 구현할 계획입니다.

![전체 시스템 흐름도](docs/assets/system-overview.png)

흐름도는 기획 단계의 개념도이며 구현 및 설계 변경에 따라 갱신합니다.

## 초기 대상 범위

- **병과:** 내과
- **약물군:** 고혈압, 당뇨, 고지혈증, 위염·위장관계 의약품
- **제형:** 정제·캡슐 중심
- **포장:** 약포지, 통약 박스·용기, 낱개 PTP

초기 PoC에서는 선정한 품목으로 기술적 가능성을 검증합니다. 구체적인 품목 목록과 데이터 규모는 확보 수준에 따라 확정하며, 산제·시럽은 초기 범위에서 제외합니다.

## 기술 스택 계획

| 파트 | 주요 기술·구성 |
| --- | --- |
| AI① 의약품 인식 | Python, PyTorch, Ultralytics YOLO, PaddleOCR 우선 검토, OpenCV |
| AI② 비교·오류 분석 | Python, 규칙 기반 비교 로직 |
| Backend | FastAPI, MySQL, SQLAlchemy, REST API, JWT |
| Frontend | React, TypeScript / JavaScript, Flutter, Dart |
| Hardware | USB 카메라, LED 조명, 편광필터, 고정형 촬영 구조물, ESP32, 감지 센서 |
| 개발·협업 | Git / GitHub, Docker, Figma, CVAT |

세부 기술과 부품은 실험 및 상세 설계 결과에 따라 확정합니다. HW는 고정형 촬영 Station부터 시작하고 촬영 자동화와 자동이송은 단계적으로 검토합니다.
